# Mini XUI

面向个人单机使用的轻量 Xray 管理面板。管理已有的 VLESS + Reality 和 Hysteria 2 + TLS 入站，在页面上配置用户、生成二维码并查看流量。

Mini XUI 是管理面板，**不包含 Xray，也不会自动安装、创建节点或申请证书**。项目以 Go 编写，页面内嵌，无前端构建步骤；二维码使用 `go-qrcode` 依赖。

## 功能

- 查看已有入站；编辑端口、Reality 参数及 Hysteria 的 TLS 参数。
- 添加、编辑、删除用户，生成分享链接和二维码。
- 查看用户累计流量、周期平均速率和近期活跃状态。
- 保存前使用 Xray 校验配置，保留一份配置备份。
- 可选地通过页面重启指定的 systemd 服务，让已保存的配置生效。

目前不支持从页面新建或删除入站、订阅服务、导入 3x-ui 历史流量、流量限额、到期管理或图表。它不会管理其他 Xray 实例。

## 运行要求

- Linux；启用页面重启按钮需要 systemd。
- 已安装与配置兼容的 Xray，并有一份**独立管理**的 Xray 配置。
- 至少一个已有的 VLESS + Reality 或 Hysteria 2 + TLS 入站；配置文件使用 Xray JSON 格式。
- 构建需要 Go 1.22 或更新版本；运行时不需要 Go。
- 面板进程需要读取 Xray 可执行文件、读写配置目录和统计文件目录；如果使用页面重启，还需要重启指定服务的权限。

分享链接需要公网 IP 或域名；Hysteria 需要可用的 TLS 证书。服务端端口必须在主机和云平台防火墙中放行。当前提供的二进制需针对目标操作系统和 CPU 架构构建。

## 构建与启动

在仓库目录中执行：

```sh
go build -o mini-xui .
```

准备已有的 Xray 配置，并确认配置里的 Stats API 已启用、Xray 进程正在运行。以下路径和地址仅为示例，请替换成自己的值：

```sh
# 建议通过权限受限的环境变量文件或服务管理器设置密码。
export MINI_XUI_PASSWORD='替换为自己的强密码'
./mini-xui \
  -config /path/to/xray/config.json \
  -xray /path/to/xray \
  -api 127.0.0.1:62789 \
  -stats /path/to/traffic.json \
  -public-host your-server.example.com
```

`-api` 必须与 Xray 配置的 API 入站地址一致；上面的端口仅是示例。`-public-host` 用于生成分享链接，应填写客户端可访问的公网 IP 或域名。查看完整选项：`./mini-xui -help`。

面板默认监听 `127.0.0.1:8080`，只允许绑定回环地址。在自己的电脑上建立 SSH 隧道：

```sh
ssh -L 8080:127.0.0.1:8080 user@your-server.example.com
```

然后访问 `http://127.0.0.1:8080`。面板不提供 HTTPS，也没有面向公网部署的认证机制，请通过可信的 SSH 隧道访问。二维码和链接包含客户端凭据，不要公开分享。

## 保存与应用配置

面板编辑的是 `-config` 指向的文件。保存时，程序先运行 `xray run -test`，验证通过后将原文件保存为同目录的 `config.json.bak`（实际名称为配置文件名加 `.bak`），再替换配置。每次只保留一份备份。面板需有目录写入权限；配置与备份以 `0600` 权限写入。

保存后需要重启相应的 Xray 才会生效。配置文件里的端口冲突会被检查，但面板无法保证端口没有被其他进程占用，也不会修改防火墙。更改连接参数后，客户端可能需要重新导入。**分享链接使用已保存的配置；重启前它可能与正在运行的配置不同。**

若 Xray 由名为 `mini-xui-xray.service` 的 systemd 服务管理，启动面板时添加：

```text
-restart-service mini-xui-xray.service
```

页面会显示“重启并应用配置”：先采集流量、校验配置，再重启该服务并检查状态。面板进程须有相应 systemd 权限；重启会短暂中断连接。失败时不会自动回滚，可使用 `systemctl status mini-xui-xray` 和 `journalctl -u mini-xui-xray` 排查。未启用此选项时，请自行重启 Xray。

## 使用现有 3x-ui 配置

3x-ui 可能根据自己的数据库重新生成 Xray 配置，**不要让两个面板管理同一个配置文件或共用同一个 Xray 实例**。迁移或并行测试前，先备份 3x-ui 数据库、证书和生成配置，将配置复制到独立位置，并使用兼容的 Xray 版本验证。

并行运行时须使用独立的代理端口、Stats API 和其他监听端口。证书路径应在新环境中可用；还要检查并保留续期机制。原有订阅功能及 3x-ui 历史统计不会自动迁移。先验证新实例，再安排切换。

## 流量与活跃状态

Xray 配置需要启用 StatsService、用户上下行统计及在线统计；每位用户必须有全局唯一的 `email`。面板默认每 30 秒读取非重置计数，并将累计值写入 `-stats` 指定文件；首次采集会包括当前 Xray 进程已累计的计数。平均速率按两次采集之间的流量计算；活跃状态由 Xray 返回，通常表示约 20 秒内有连接活动，并非逐连接明细。

统计基于轮询，Xray 在两次采集之间重启、面板停止期间 Xray 重启或统计文件丢失时可能漏计或丢失历史，**不适用于精确计费**。删除用户不会自动删除已有历史统计。

## 安全与备份

面板密码通过 `MINI_XUI_PASSWORD` 环境变量传入，当前程序要求至少 8 个字符；实际使用建议设置更长的随机密码。避免将真实密码写入仓库或共享 shell 历史。限制配置文件、环境变量文件、证书和备份的访问权限，并自行备份。

当前页面重启功能会执行固定的 systemd 服务操作，因此需要具备相应权限。部署时应明确这些权限，避免将面板或 Xray API 暴露到公网。不要将真实的配置、私钥、数据库、流量文件或节点链接提交到公开仓库。
